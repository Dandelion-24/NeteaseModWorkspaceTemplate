# ModSDK 开发核心

先读根规则、任务组件说明与已有接口核对记录。遵循已授权范围；一个局部修复不自动重做产品、UI 或数据架构。

## 先核对，再实现

新增或修改引擎接口、事件、JSON 组件及其组合前，按 `docs/mcdocs/` → `docs/mcguide/` → `docs/mconline/` → 同目标已运行代码查证。**实际打开命中的正文，不只看搜索结果、索引、方法名或邻近示例。** 使用[接口合同核对表](references/api-contract-checklist.md)，记录依据与调用位置；已有有效记录可复用，只复核本次变化。

默认目标读取[当前平台基线](../../../../docs/PLATFORM_BASELINE.json)，具体以组件兼容声明为准。新正式版确认后按根规则及 `docs/README.md` 同步默认基线、正文和受影响约定；已有组件另做兼容迁移。引擎版本、文档版本、各 JSON 格式版本和包版本分别核对，不按 SDK 号猜接口或格式。

查不到、资料矛盾或目标档位不明时，写清缺口并先完成不依赖它的工作；受影响实现保持待核对。需要关键探针时使用最小受控场景；不凭记忆补接口，不用同名国际 API 或猜测别名兜底。

## 必须闭合的数据流

- 注册真实系统类，监听发送方所属的正确系统。逐事件核对实例方法绑定、回调参数个数、字段拼写和类型；引擎事件与按钮回调不因都叫回调就视作同一合同。
- 从可信引擎事件或文档规定的注入身份取得玩家。候选坐标、槽号、模式等仅作有界请求，服务端重新读取并验证真实目标、维度、距离、归属、版本和当前状态。
- 发送字段、服务端白名单、字段类型与响应消费保持一致。修改事件的取消字段时核对是否必须写回原始参数对象；限频/去重不能跳过必要的取消和保护。
- **返回值形状照正文处理。** 单 dict/int/坐标不能自行解包成 `(ok, value)`；项目包装器也要声明自己的成功/失败返回形状。空槽、合法空列表、未就绪、未加载与读取失败分别处理，不用猜测的默认值掩盖错误。
- 写操作区分返回成功、完整读回和后续状态。物品/世界事务考虑重复请求、部分成功、未决结果与重进恢复；未对账时不盲目重发扣除、发放或放置动作。
- 持久化确认宿主、作用域、可写时机、类型、序列化与保存要求；用不同形状、中文/ASCII、空值、容量和重进分别核对。不要把某次环境观察固化为所有接口的限制。

## 写错风险与诊断

- 游戏代码保持 Python 2.7 兼容，宿主脚本分开；显式处理 bytes/Unicode、bool/int/long 与参数边界。纯逻辑模块不在导入时依赖引擎。
- 核对跨模块成员、常量导入、辅助函数作用域和生成后的实际文件。不要用改名字、宽泛 `except`、静默 return 或“返回成功”替代缺失实现。
- 生命周期、定时任务和回调有可见失败路径、限次诊断与清理。日志覆盖接收、验证、调用、读回和结果，并保留能定位失败的类型/键名摘要，避免刷屏和泄露完整私人数据。
- tick 不是实测时钟。需要观察后续状态时，用有界幂等读回并从实际执行时点计算间隔；非幂等写操作不按“重试”重复执行。调整期限先检查前置条件和保护动作本身。

有菜单或 HUD 时按[界面质量合同](../netease-visual-assets/references/ui-ux-quality.md)实现就绪、切页、关闭和晚回包状态。客户端可先显示处理中，不能将预测当成服务端已确认成功。

## 验证与交付

修复问题先记录构建、现象与最短复现，沿数据流定位首次合同不一致的位置，并检查同类调用者。涉及身份、物品、世界写入或恢复的修复，保留原失败场景与必要正常/边界回归；未重现或未执行的项明确保留，不靠相似旧案例宣布根因与修复完成。

按改动风险运行项目校验和必要的宿主/游戏回归；投稿前另跑 pylint。静态解析、宿主仿真、游戏运行和平台审核分开报告。交付改动范围、接口依据、数据流、测试结果与仍未知的边界。
