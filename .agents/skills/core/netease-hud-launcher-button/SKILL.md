# 常驻 HUD 菜单入口

先读组件输入约定、相关本地接口和[界面质量合同](../netease-visual-assets/references/ui-ux-quality.md)。没有 HUD 的组件不自动添加入口；已有产品交互优先。

## 交互可选，结果必须一致

未另有约定时可采用轻点开关、长按后移动拖动的模型。按钮风格、大小、阈值、是否可拖和指针解锁按任务确定，不继承其他组件的常量。按实际时间与移动量识别手势，不能把 tick 差值直接换成实测按压秒数。

核心开关操作在 PC 和手机都可完成；拖动不能误提交点击或漏给世界操作。隐藏面板、关闭会话与保留预览若是不同状态，要明确并让所有入口一致处理。

## 先核对输入链

- 按本地正文核对按钮事件注册、回调参数和吞输入行为；PC 鼠标与触屏 Move 不预设相同。确有需要时使用经核对的轮询或替代路径。
- PC 解锁指针可按经核对的 `OnKeyPressInGame` 与 `SimulateTouchWithMouse` 实现；具体键名、字段类型与释放时机查合同，不写猜测别名。
- 装饰图标和文字不能意外吞点击；需要自身交互的子控件显式分工，不把所有子控件一律禁用。
- 初始位置优先 JSON 锚点；运行期移动明确单位转换与边界夹取，不把未解析的百分比当作画布像素。
- 分辨率变化、UI 重初始化、切世界和拆解时重新确认节点与输入状态。失效句柄要重取，是否重建以生命周期为据，不每帧盲目销毁重建。

## 验收

静态检查路径、手势状态、关闭/隐藏/结果入口与几何。实际测试 PC GUI Scale 3/4/5、手机横竖屏的轻点、适用的拖动、误触、出屏、遮挡、指针恢复和重进。入口标签按实际可读空间设计，不固定字数或强制某种物品图标。
