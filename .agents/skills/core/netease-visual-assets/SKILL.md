# 视觉资产与界面质量

先读组件视觉约定与相关本地文档。区分几何模型、纹理、物品图标、界面图像和 JSON 布局：图片不代替模型，装饰底图不代替文字与交互控件。

## 默认建议与设计自由

未指定视觉方向时，默认贴近游戏原生的尺度、材质和交互习惯，并优先复用已核对的原生控件。已有组件风格或用户明确选择优先；深色、明亮、简洁、工业、奇幻等方向均可，不能因偏离原生配色而判不合格。

先按现有要求形成简短视觉简报：用途、显示尺度、像素密度、透明度、主要材质/轮廓、调色板、对比和资产家族。信息不足但不影响推进时使用合理默认，不把“写简报”变成额外审批。颜色数量、固定面板尺寸、图标形状和九宫参数由资产与任务决定，不照搬其他组件的数值。

## 质量硬约束

- 所有菜单与 HUD 遵循[跨端界面质量合同](references/ui-ux-quality.md)：结构清楚、文字与命中区不冲突、状态可辨、关闭和晚回包正确。
- 一组资产在轮廓、边框、像素密度、材质、明暗和留白上保持一致；小图优先明确的识别重点与足够占比，避免细碎装饰压过内容。分类差异能在实际尺寸下识别，不只靠颜色。
- 文案、数字和动态状态由 JSON 文本/交互控件承担；重要信息不被裁剪、背景或选中高亮遮住。图片拼出的外观不能替代真实控件的命中与状态逻辑。
- 检查 UV、原点/枢轴、面朝向、纹理比例、透明边、拼缝、图集和资源绑定；具体坐标与模型约定以对应格式正文为准，不能把一个模型的坐标范围套给全部模型。
- 正常、按下、选中、禁用和加载等适用状态要保持辨识与一致性。引用原版模板或图片时先核对其真实定义和拉伸参数，不按名字猜效果。

## 制作与验证

需要位图生成/编辑时使用当前可用且适合任务的图像工具；没有相应能力时说明资产缺口，继续完成不依赖它的布局或资源接线，不伪造成品。原生资源复用、已有素材导入与用户指定转换是独立路线，不因有图像模型而强制重新生成。

不以程序色块、随机噪点或含假文字的原始出图冒充正式美术。已有图片的授权裁剪、尺寸/调色板转换可以按任务进行，保留源和转换记录；处理后的结果仍需人工审阅。简单布局、间距与底色可由 JSON 控件承担，无需为装饰额外生成图片。

模型按已核对的 MCStudio/Blockbench 工作流制作；客户端渲染资源放 RP，UI 行为逻辑放 BP。新资源按代表性样本先验证轮廓和可读性，再按实际范围扩展，避免未经审阅一次铺满全部资产；已有授权足够时直接推进。

静态核对命名、JSON、图集、UV 和引用。实际显示检查正常尺寸与放大预览、模型多面拼缝、GUI Scale、手机横竖屏和适用状态。报告具体覆盖与剩余风险，不继承参考项目的运行结论。
