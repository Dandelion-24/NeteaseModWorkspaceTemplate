# 运行日志复盘

先确认目标组件、构建、端侧、场景和采集通道。日志缺少这些信息时标明归属不确定，继续分析可以确认的内容。仅复盘任务只读；用户同时要求修复时，先定位问题再按对应开发技能修复，不因本技能的只读分析阶段重复索要已有授权。

1. 摘要时间范围、行数、引擎异常、组件警告与关键码，合并连续重复项。按目标协议提取拒绝、超时、重试、未决和回滚，不固定某组代码，也不要求合理的拒绝计数必须为零。
2. 关联请求、动作、API 返回、读回与结果；改动未触发或缺少关键阶段时明确未覆盖。时间按时间戳与实际执行记录分析，不把 tick 差值当成秒数。
3. 检查不带组件前缀的导入/引擎错误，也按时间和栈排除无关消息。看到一条注册日志不足以证明全部加载成功；日志中无错误也不能证明渲染、点击或状态正确。
4. 参数拼写、类型或返回形状有嫌疑时回查[本地接口合同](../netease-modsdk-core/references/api-contract-checklist.md)，不靠日志猜一个字段名。只记录所需的类型/键摘要，分享前处理账号、路径和世界隐私。
5. UI、模型与文字问题结合截图和操作证据，按[质量合同](../netease-visual-assets/references/ui-ux-quality.md)定位；日志没有记录的像素层级、触控命中和键盘遮挡不能判通过。

输出“直接证明 / 只能推断 / 未覆盖”的结论，并给出具体窗口、计数、影响与适量补测。错误归因要有相应证据；不知道就说明需要什么，不把相似旧案例当本次根因。

原始日志保留原字节；摘要与必要证据入口迁入组件维护记录。临时分析文件按授权放 `tmp/`，不把私人原始日志或项目事故复制进公开模板。
