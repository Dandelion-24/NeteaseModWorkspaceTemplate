# MCStudio 与 Add-on 交付

读取根规则、组件说明和当前工程 README。按用户已说明的目的地工作，只有目的地影响包结构且确实不明时才澄清。打包与发布是不同操作；已有上传授权不重复询问，只有打包任务不自行投稿。

## 包结构与完整性

1. 根据实际工程确认 BP/RP、Manifest、模块 UUID、包版本与依赖。模板默认目标读取[当前平台基线](../../../../docs/PLATFORM_BASELINE.json)，既有工程按兼容声明核对；正式版更新后同步适用的打包规则与校验。最低引擎版本、当前目标、Manifest 格式和包版本分别核对，不按 SDK/引擎号推算格式。
2. 运行适用项目检查，解决源码、接口合同、事件、资源和引用失败。工程生成器改动后读回实际 JSON 与打包内容；报告不能替代生成文件。
3. 使用已有或按任务编写的打包器，输出到工程 `deliverables/`：MCStudio 导入包根为 `behavior_packs/` 和 `resource_packs/`；Add-on 投稿包根为具体 `<BP>/`、`<RP>/`，不套项目名或前述包装层。
4. 逐包检查条目名、Manifest、CRC、重复项、与预期源文件的字节一致性，以及缓存、私人状态、临时文件和无关内容排除。开发说明与工具不进入 Add-on 运行包。

指南类物品按实际功能检查独立 ID、定义、图集、PNG 与书本配置；无需指南的组件不为套流程自动增加物品。UI/模型/纹理有变时按[质量合同](../netease-visual-assets/references/ui-ux-quality.md)检查所影响状态与端侧，风格可以不同；已有实测只对其确切版本、构建和范围有效。

## 投稿辅助检查

打开本地 `docs/mcguide/50-常见问题答疑/60-我的世界中国版打包错误信息汇整.md` 与 `docs/mcguide/35-上架与入驻/课程11-我的世界中国版资源上传规则.md`。新投稿核对适用正式规则；常见项包括 10/24 的包识别与根目录、16/27 的名称与路径、35 的命名限制、37 的引擎声明、42 的升级版本和 21 的加密源包限制。工作区脚本只覆盖其中部分，不猜测未公开的机审实现。

```text
python dev_tools/check_pylint_errors.py <behavior-pack-dir> --out <report>
```

参数为 `--disable=all --enable=E --disable=E0401 --score=no`。记录解释器和 pylint 版本，区分真实错误与 Python 2/引擎模块的环境差异。通用示例或本地通过不保证平台工具链相同或审核通过。

## 加载诊断与证据

缺包警告先查根布局、Manifest 和世界激活清单的 UUID/version，再查 Python 导入、事件与 UI；资源可见不证明脚本加载成功。世界挂载与交互必须由实际环境证据确认，离线 ZIP 不能证明启用状态。

交付用途、路径、版本、实际静态结果、确切运行证据与剩余项。仅工具/文档整理时保护原运行包字节，不擅自改玩法版本。平台提交、审核与上架状态不由本地构建重置。
