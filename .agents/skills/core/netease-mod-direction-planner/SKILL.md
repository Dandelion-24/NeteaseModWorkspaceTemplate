# 模组方向规划

先读用户题材、排除项与团队约束，再看根规则、工作区说明和 catalog。具体组件仅在相关时读取；一次选题偏好不变成永久规则。纯脑暴或对既有方案的文案整理不自动立项、创建工程、补全市场研究或报名投稿。

## 研究范围与证据

完整选题/市场判断进行新的中英文检索，覆盖中国版直接竞品、国内外社区/资源、视频反馈和网易官方渠道。用户限定题材、来源、候选或仅要轻量创意时按范围执行，未调研的创意明确标为假设，不伪装成市场结论。规则维护不自动重跑调研。

| 类别 | 入口与提取内容 |
| --- | --- |
| 中国版供给 | 网易资源中心、可访问的作品详情、作者发布与组件码；核对端侧、版本、当前在架和可见评价 |
| 社区/资源 | MCPEDL、苦力怕论坛及相关 CurseForge、Modrinth、Planet Minecraft 等；提取机制、更新、需求与反例，区分 Java、国际 Bedrock 和中国版 |
| 视频 | B站、YouTube、TikTok 及相关平台；玩法表现、评论与可核验互动，未观看/未读评论的部分单独说明 |
| 官方 | 网易开发者官网、正式文档和活动正文；版本变更、资格与时限，不从旧摘要判断仍在进行 |

优先打开原作者页面与具体评论。记录来源、日期、平台/版本、机制、需求、问题和指标口径；搬运、同作品不同包和重复讨论不重复计独立需求。区分作者宣传、玩家原话、数据与自己的推断，保留卡顿、存档、移动端和原版替代等负面样本。

用户已有授权会话且实际可访问时，可只读核对[作品榜单](https://mcdev.webapp.163.com/#/statistics/depWorkList)。榜单类别、统计窗口和采集范围分别记录；不扩展到账户、收益或提交操作。登录/反爬受限就用公开来源继续，写明实时在架、销量、评分或评论的缺口；未访问/未检出不等于没有竞品。

下载、播放、点赞、搜索指数、收益排名与留存不能混算；累计量不代表独立玩家，不同年龄和平台的作品不直接混排。没有数据不猜销量、收益或“蓝海”。参考作品用于提炼机会，不默认移植其代码、素材或完整设计。

## 竞争、差异与题材

按候选名称、同义词和玩家目标检查中国版同类。热度说明需求线索，竞争说明进入难度；既不因热门就推荐，也不因存在竞品就一票否决。用户已选方向仍可实施，报告风险与可兑现的有限首发，不擅自换题材。

玩法/管理组件的差异落实到核心循环、用户流程、约束、协作或原版替代不足。装饰、视觉、内容题材可以靠造型语言、制作质量、主题内容与使用体验形成价值，不强制所有题材都新增机制；单纯改名或未经证明的“更完整”仍不足以支撑结论。

## 官方更新与技术可行性

以检索当天北京时间为准核对活动名称、链接、起止/时区、资格和提交要求，区分进行中、将开始、已截止与未知。只报告机会，不自动报名或承诺获奖。

先读 `docs/SOURCES.json`、`docs/SYNC_STATE.md` 与 `docs/UPSTREAM_SOURCES.md`，检查本机 `docs/LOCAL_MANIFEST.json` 是否存在，再核对相关正式页面。发现新版正式文档按 `docs/README.md` 从允许的来源更新本地文本，beta 不覆盖正式资料，组件目标不自动升级。访问不到就保留已有时点和缺口，不写“无更新”。规划讨论不自行抓取整库或将资料缓存公开。

把决定卖点的操作拆为输入、目标识别、世界修改、物品事务、持久化、UI、模型与移动端要求，按 [ModSDK 核心](../netease-modsdk-core/SKILL.md)和[接口合同](../netease-modsdk-core/references/api-contract-checklist.md)实际查正文。不能从接口存在推导整套组合可行；视觉/菜单工作量按[界面质量合同](../netease-visual-assets/references/ui-ux-quality.md)评估，不在规划阶段锁死风格与页数。

可行性标“文档支持 / 需关键探针 / 暂缺平台依据”，说明依据、关键限制、最小验证和缩减路线。静态、宿主、游戏与发布证据分别记录；新方向没有游戏证据就明确未实测。

## 产出

在对话给候选表或编号列表，包含核心循环/内容价值、需求与竞品证据、差异、有限首发、技术标签、相对代码/美术/内容/手测投入和推荐理由；数量随有效证据和问题决定。未了解人力不编工期。活动、文档变化和访问缺口简述即可。

长期记录放带日期与来源的 `dev_tools/reports/`，正式立项再建组件。授权清理旧候选时核对身份、当前引用和范围；正式设计、运行证据与其他保留资料不自动包含。
