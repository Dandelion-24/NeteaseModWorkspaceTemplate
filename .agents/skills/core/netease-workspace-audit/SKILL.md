# 工作区审计

读取根规则并明确检查范围。单组件实现检查交给项目校验；本技能补充全区关系、共同约束和文档一致性，不因一次普通改动自动扩大到所有工程。

## 现有只读工具

```text
python .agents/skills/core/netease-workspace-audit/audit_workspace.py [workspace-root]
python dev_tools/verify_local_environment.py --profile source
```

第一个脚本检查游戏工程；第二个核对轻量模板核心和已安装资源，源码模式允许可选资源尚未安装。需要资源检查时加 `--task <任务>`；全部资源校验用 `--profile full`。文档和工具未就绪必须单独报告；两个脚本均不自动修复。空模板通过不代表已有运行组件。

| 范围 | 脚本覆盖及局限 |
| --- | --- |
| ZIP、Manifest | 指定用途布局、CRC、重复项、缓存、格式/版本/依赖与 UUID；未知用途包仅有限检查 |
| Python、UI | 常见 Python 3 语法风险、UI 登记和部分结构风险；不是完整 Python 2 解析器或 UI 渲染器 |
| 物品与噪声 | BP/RP 定义、图集/PNG 链和包内缓存 |
| catalog | 当前/历史/设计/资产/交付/技能/证据路径；不含完整 schema 校验 |
| 结构原件 | 按文件名匹配副本哈希；无匹配或同名多源需人工定位 |
| 共存 | 资源路径与部分标识符重叠；可合并表仍要人工检查内部键冲突 |

UI 按[质量合同](../netease-visual-assets/references/ui-ux-quality.md)复核结构与证据，不把原生风格、另一种配色或某个继承模板本身当作问题。脚本没有覆盖的判据不能写成“已自动验证”。

## 人工核对与修复范围

- 对照 catalog、组件说明、当前 README、手测、运行记录、交接与发布证据；版本、路径和证据范围一致，根规则不复制私有项目台账。
- 区分当前引用、历史当时路径与生成物；逐个核对带版本文件名，防止半替换与悬空指针。
- 按资源真实合并方式检查：表文件的内键、标识符资源的 ID、按路径加载资源的覆盖分别处理。相同字节通常为信息项；同组件不同版本属于替代升级关系，同世界不同时启用。
- 目录名归属当前脚本采用去掉可选 `Netease` 前缀和 `_v<version>` 后缀的启发式；不符合时按 catalog 人工映射，不能拿命名差异制造冲突。
- 清理前检查测试/比较器依赖、保留必要证据与最小回归源，再按已有授权修改具体路径。仅要求审计时保持只读；明确要求修复时处理已确认问题，不重复询问已有授权。

## 报告

失败、警告与已验证范围分开；说明依据、影响、修复或待测。实现事实有疑问时回到本地接口合同，不把扫描命中升级成平台定律。游戏和发布证据独立，运行盲区保持待测。改变审计器后运行其回归；只改技能文字时检查规则语义、路由和引用，不制造无意义代码测试。
