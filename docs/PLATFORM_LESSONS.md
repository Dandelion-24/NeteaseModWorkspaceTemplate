# 平台核对与回归清单

通用平台核对方法。接口事实以对应正式正文为准，组件版本、运行边界和验证证据保存在各自工程。

## A. Python 2 运行边界

- 交付给引擎的代码保持 Python 2.7 兼容；宿主维护脚本使用 Python 3，两者分开。
- 对文档允许的字符串区分 `str` / `unicode`；在公共边界集中定义兼容类型，不依赖模板中不存在的模块。字节解码、中文截断和展示需分别验证。
- 宿主解释器中的标准库、整数类型与第三方包能力不自动等于引擎能力。关键摘要、序列化、日志等辅助路径也要覆盖。
- 使用当前平台支持的日志接口；格式化后传入消息，确认能从实际采集通道看到，并避免输出凭据和完整私人数据。

## B. 静默失败排查

- 新增或改变的调用按[接口合同核对表](../.agents/skills/core/netease-modsdk-core/references/api-contract-checklist.md)实际读正文，记录端侧、宿主、完整签名、字段拼写、返回形状、空值/失败语义与消费路径。索引命中或同名方法不能代替核对。
- 先证明 BP/RP 挂载、Python 系统注册和客户端/服务端事件通道，再排查具体功能。JSON 资源可见不代表 Python 已加载。
- `modMain` 的导入与系统类注册须核对本地文档；若出现 `ImportModMain` 或 `module object is not callable`，检查实际导入对象和异常栈。
- 回调参数名、类型和是否有参数都照正式事件表核对。`OnScriptTickServer` 的无参约定不要机械套用到其他事件。
- 自定义请求的事件登记、字段白名单和类型校验保持同步。服务端从引擎注入身份取得发送者；`__id__` 的来源说明见 `mcdocs/1-ModAPI/接口/通用/事件.md`。
- 拒绝、组件获取失败、资源缺失和异常须有可关联的原因。用限次、限频诊断区分“没有事件”与“事件字段不符”。
- UI 的创建、关闭与在途回包都检查生命周期状态；关闭后旧结果不得重新显示界面或预览。
- `PopScreen` 等方法按当前正文签名调用；不能靠吞异常判断关闭成功。

## C. 世界操作、容器与持久化

- 原生返回与项目包装器的合同分别检查。单 dict、整数、坐标或合法空结果不能自行当作 `(ok, data)`；未加载、未就绪和读取失败不能用假定默认值混过去。
- 世界修改参数由服务端验证并计算。分别检查 API 返回值、立即读回和后续状态；容器、方块实体、红石与实体时序不能仅靠返回成功推断。
- 原生容器、自定义方块实体、漏斗和 UI 组合先逐字段核对，不因独立能力存在就推断可组合。参考 `mcguide/20-玩法开发/15-自定义游戏内容/2-自定义方块/3-特殊方块/11-自定义容器.md` 与相邻 `4-自定义方块实体.md`。
- 持久化按形状测试：字典、列表、数字、ASCII、中文、嵌套及容量分别写入独立键，读回、重进、清理后再核对；单次复合失败不足以归因某种类型不支持。
- 配置名与数据内容分别遵守各自限制。不要把配置文件名、资源命名空间与 ExtraData 键当作同一种契约。参考 `mcdocs/1-ModAPI/接口/通用/本地存储.md`。
- 物品数据保真按背包移动、容器往返、掉落拾取、重进世界逐项验证，不把一次读写视为全链路通过。

## D. JSON UI 与输入

- 按[跨端界面质量合同](../.agents/skills/core/netease-visual-assets/references/ui-ux-quality.md)检查结构、状态、输入和可读性；原生是默认建议，其他风格可用，不从某个组件照搬尺寸、配色或固定分页方式。
- 先核对 `mcguide/18-界面与交互/30-UI说明文档.md`，再检查 UI 注册、根 screen、继承、变量作用域、控件路径与生命周期。
- 自定义按钮可采用 `button + child label`；回调按正文注册。继承模板和状态变量需验证实际作用域，不能靠关键词出现与否定罪。
- 像素尺寸与 UI 单位分开。优先用 JSON 锚点与经过验证的布局；尺寸描述中的百分比与绝对量不能当作已解析画布尺寸。
- PC 与手机分别验证点击、拖动、输入框、滚动或分页、关闭与重进。某一端收到 Move 回调不代表另一端也会收到。
- 面板行区、分页和底部操作保留独立命中区域。字号、居中、留白和宽窄布局在 GUI Scale 与手机横竖屏中检查，不把固定字符数或某台设备尺寸当成普遍规则。
- HUD 与模态菜单按当前产品约定选择；子控件命中、界面遮挡、分辨率变化与节点重建需回归。

## E. 时间与流程

- tick 是调度计数，不是实测秒数。对真实延迟记录时间戳，并验证阻塞调用与负载后的行为。
- 需要观察后续状态时，采用有界、幂等、可重复的读回检查；重试间隔从实际执行时点重算。设置上限和失败终态。
- 重复观察不等于重复写入。扣除、发放或放置等非幂等动作结果未知时先对账，避免修复流程制造重复执行。
- 改期限前先列出前置条件、重试与保护动作的关系，避免只改一个不起作用的数字。
- 修改生成器后读回生成的文件；报告、生成源和实际包内容分别核对。

## F. 探针与证据通道

- 文档核对、静态检查、宿主仿真、游戏运行与发布证据分开，方法见 [PROBE_METHOD.md](PROBE_METHOD.md)。
- 每次运行记录构建、目标档位、端侧、场景与覆盖项。没有执行记录的项写 `NOT_RUN`。
- 引擎日志、脚本日志与 UI 截图相互补充。前缀过滤用于摘要，原始日志仍须检查不带前缀的导入异常与引擎错误。
- 原件按原字节保存；长期引用放工程 `validation/` 等受维护位置。分享前复核日志、路径、账号与世界数据中的私人信息。

## G. 工程与交付

- 当前版本、包版本、依赖、catalog、工程说明、测试清单和交付文件名保持一致。历史证据不随升版改写。
- MCStudio 导入包与 Add-on 投稿包使用不同根布局，分别验证 Manifest、CRC、重复项、缓存和无关内容排除。
- 投稿前运行 pylint 错误级辅助检查，并记录版本与参数；本地结果不能保证平台结果。
- 通用工具与专属项目分开。添加规则时写明适用范围和验证方法；公开模板不保存个人项目事故或专属技能。
